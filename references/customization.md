# 从当前证据生成本地定制脚本

通用 Skill 提供测量能力；每台电脑的用途、保护对象和后续调查不同。不要把用户交付的历史脚本直接变成下一台电脑的默认行为。

## 先获得足够的证据

从 `doctor` 和首次有范围的 `collect` 读取：

- 启动容器、真实可用空间、Data 卷占用与当前扫描范围。
- 占用最大的目录、它们所属的应用或项目、扫描是否完整。
- 权限拒绝、超时、未展开云端目录、挂载边界以及原始证据位置。

先记录推断，再用有范围的只读命令验证。比如只有确认目录属于真实项目且存在构建配置之后，才将该项目列入 `project_roots`。应用历史、数据库、源文件、版本库、工作树、当前工具链和正在使用的数据需要明确保护；不存在的路径不作为检查成功的证据。

## 生成本地案例

在 Skill 和项目仓库外选择目录。例如令 `LOCAL_CASE` 指向当前用户 Application Support 下一个新案例目录：

```sh
python3 "$SKILL_DIR/scripts/storage_inspector.py" make-local --destination "$LOCAL_CASE"
```

生成目录包含：

- `profile.json`：该机器的路径列表；共享模板中的列表为空。
- `investigate_local.py`：可执行的调查脚本，默认动作是 `plan`。
- `.gitignore`：整个案例目录忽略跟踪；脚本运行后 `state/` 也留在案例内。

配置示例（路径只是格式示例，不可不经核对就扫描）：

```json
{
  "schema_version": 1,
  "targets": ["${HOME}/Library/Caches"],
  "project_roots": [],
  "protected_paths": [],
  "log_roots": []
}
```

`${HOME}` 在运行时解析为当前用户的主目录。其他路径必须是绝对路径。列表不支持 shell 片段、命令替换或通配符执行。只填当前调查实际需要的路径。

随后实际完成机器专用脚本：保留公共工具的调用接口，将问题特有的额外检查放在本地 `investigate_local.py`，并把选择这些检查的证据写在本地说明中。允许的检查示例包括元数据增长采样、指定路径的打开文件列表、具体项目的 Git 状态、包管理器只读信息。不要默认引入某个软件、个人目录命名或另一台电脑的清理清单。

## 执行并复核

```sh
python3 "$LOCAL_CASE/investigate_local.py" plan --skill-dir "$SKILL_DIR"
python3 "$LOCAL_CASE/investigate_local.py" scan --skill-dir "$SKILL_DIR" --seconds 20 --budget 120
```

`plan` 必须输出与当前证据匹配的目标目录及保护配置。`scan` 不删除文件，所有目标共用一个遍历预算；卷信息查询和构建的时间另计。没有目标时扫描会拒绝执行，避免把空模板误当作已完成的定制。

核对新报告中的时间、范围、错误、云端占位和实际占用。需要看应用是否仍写日志时，再加有次数及期限的采样，不开启无限监视。

如果需要清理，先确认用户的具体授权。清理脚本另存本机，默认输出计划并拒绝目标漂移：固定明确路径，拒绝符号链接替换、根目录和越界路径；预检进程占用及 Git 改动；记录保留项，测量执行前后容器空闲空间。历史文件中“已批准”或旧日期不代表今天的授权。

## 本地保留和分享前检查

本地定制目录应与共享 Skill 在物理路径上分离，并由当前用户私有访问。不要为了分享而把定制文件放进 Skill 后仅依赖 `.gitignore`。

归档只采用固定的共享文件名单。打开最终 zip 成员清单并扫描文件内容，确认没有真实用户名、主目录、主机标识、应用历史、报告、配置或一次性清理脚本。若用户要求不上传，不执行远程建仓、push 或附件上传。
